# Finder стендов Giga Cowork

Проект содержит два Python-скрипта для поиска стендов (`config.yaml`) в Git-репозитории `argocd` по `cowork_subdomain`, `admin_email` или `ИНН`. Скрипты автоматически обновляют репозиторий, рекурсивно ищут конфиги в заданных зонах и выводят информацию о найденных стендах.

**Репозиторий на GitHub:**  
[https://github.com/U1traLich/finder](https://github.com/U1traLich/finder)  
Клонирование: `git clone git@github.com:U1traLich/finder.git` или `https://github.com/U1traLich/finder.git`

---

## Версии

### 1. `finder_sbs.py` (базовая версия)
- Простой поиск с выводом результатов.
- После поиска предлагает открыть `admin-helper-new.html` и ArgoCD для найденных стендов (с выбором, если их несколько).
- **Плюсы:** минималистичный, быстрый, подходит для быстрого поиска.
- **Минусы:** не позволяет редактировать параметры стенда.

### 2. `finder-pro.py` (расширенная версия)
- Включает всё, что есть в базовой версии.
- **Дополнительно:**
  - После выбора стенда появляется меню действий:
    1. Открыть Admin Helper и ArgoCD
    2. Изменить `expiry_date` (срок действия)
    3. Изменить `admin_email` (администратора)
  - Изменения **не коммитятся автоматически** – они только записываются в `config.yaml`.
  - При выходе из меню (выбор `0`) скрипт проверяет наличие незакоммиченных изменений и предлагает:
    - Автоматически сохранить изменения в `git stash`.
    - Переключиться на `master` и выполнить `git pull`.
    - Применить сохранённые изменения (`stash pop`) с проверкой конфликтов.
    - Создать новую ветку с уникальным timestamp (`feature/update-<имя_папки>-<timestamp>`).
    - Ввести сообщение коммита вручную.
    - Выполнить коммит и пуш.
    - Вывести ссылку на создание Merge Request с предзаполненным заголовком и описанием (сообщение коммита).
- **Плюсы:** полный контроль над коммитами, соответствие корпоративному процессу (ветка → MR), автоматическое разрешение конфликтов через stash.
- **Минусы:** требует ручного ввода сообщения коммита.

Примечания
Все изменения через finder-pro.py не коммитятся автоматически – это сделано для контроля над коммитами.
Перед коммитом и пушем скрипт проверяет наличие изменений и выполняет stash + pull для синхронизации с master.
В случае конфликтов при stash pop скрипт выводит информацию и останавливается – конфликт нужно разрешить вручную.
Ветка создаётся с уникальным timestamp, чтобы избежать конфликтов имён.
После пуша выводится ссылка на создание Merge Request с предзаполненным заголовком и описанием (сообщение коммита).
Если вы хотите отменить изменения, можно просто не коммитить их – они останутся локально.
